# Baseline audit — 2026-07-28

Measured on the dev stand (Playwright, both frames, default theme). Raw numbers in `measured.jsonl`. This is the
before-picture the design rules were written against; a later audit reports against it.

| Surface | height | how | surface | border-bottom | padding |
|---|---|---|---|---|---|
| `plugins/codemirror/.../CodeMirrorEditor.vue` `.codemirror-toolbar` | **40** | `var(--size-md)` | `--gray-2` | `--gray-6` | `0 8px` |

Two through a token, three literals, three content-driven. Five paddings, two surfaces, two border steps. The dialog
header is additionally set at 16px where every other strip is 14px.

`.app-header` **does not render** in the default stand — it mounts only when it has content (`e849998`). Its literal
height is a code finding with no on-screen effect.

## Panel vs page — 40 against 180

`plugins/search/src/ui/SqlConsolePanel.vue` is registered as a workspace panel but uses `PageLayout`: its header
measured **180px** (20px title, description paragraph, mono meta line, padding `24px 24px 20px`). The neighbouring tab
— a note — starts content at **40px**. One tab click moves the content start by 140px.
See `panel-note.png` and `panel-sql-console.png`.

## Row — 28 against 32, and no touch density at all

Measured (second pass, same day — the first pass could not reach the rows because the vault was empty):

| Surface | frame | height | expected role value |
|---|---|---|---|
| workspace tab | desktop | **28** | 28 ✓ |
| file tree row | desktop | **28** | 28 ✓ |
| action menu item | desktop | **28** | 28 ✓ |
| settings section row | desktop | **32** | 28 ✗ carries the control height |
| search result row | desktop | **51** | 28, wrapping ✗ content-driven, no role |
| settings section row | **mobile** | **32** | 48 ✗ **desktop density on a phone** |
| More sheet row | mobile | **56** | 48 ✗ |

Two findings the first pass missed:

1. **The touch density does not exist.** The settings rail on the mobile frame renders 32px rows — the same as
   desktop — while the More sheet renders 56px. Neither is the 48px (`--size-xl`) the rules claim, and the rail's rows
   are visibly cramped next to the sheet's. The frame does not choose the density anywhere; each surface picked one.
2. **The search result row is content-driven at 51px** (padding `4px 8px` around a two-line title + path). It is a
   legitimately wrapping row, so it should grow *down from* the role value — today it has no role value to grow from.

`NavItem` measured **32** with padding `1px 6px`: it is the rail's square icon key, i.e. a control, not a row. It
belongs to the control role and only needs its literal replaced by `var(--size-xs)`.

No 28px step exists in `packages/theme-preset/src/styles/sizing.css` (32/36/40 and halves 16/18/20) — the row role has
no token to take its desktop value from.

## Icons — three notations at once

`strip-codemirror.png`: the markdown row is uniform monochrome lucide (`H₁ H₂ H₃ | B I S <> | list, task, quote,
link`), with the file path in mono on the left.

`strip-prosemirror.png`: the same actions, one strip lower in the same product, drawn as letters (`B I S U`), a
backtick, `H1 H2 H3`, `¶`, `•`, `1.`, `❝` — and **two colour-emoji arrows** for undo/redo, which carry their own blue
tiles and follow no theme. The CodeMirror row had this exact mix and it was removed there; the ProseMirror row kept it.

Elsewhere: `✕` in `Toaster.vue` and `ChipInput.vue`, `−` in `NumberInput.vue`, against `lu:x` in six other places for
the same concept.

Icon **sizes** turned out narrower than the code implies: 12, 14, 16, 18 and 20 all appear at call sites (default 20),
but the two roles that matter both render **14×14** — measured in a strip (markdown row) and in a row (file-type
glyph). So the size rule mostly holds in practice; the exposure is the call sites free to pick a fourth number.

## Nothing enforces any of it

No test in `packages/uikit` or `packages/theme-preset`; no check for a colour literal, an off-ramp font size, or a
literal role height. Six consecutive design-fix commits in the week before this audit (`2540c4c`, `c85a743`,
`e849998`, `86e0f1f`, `0857d88`, `0744b59`) each closed one screen.

## Checked and rejected

Two suspected defects did not survive verification: the desktop app header (does not render — see above), and a
settings-nav selection that appeared to disagree with the visible page (an artefact of screenshotting before Vue
flushed; clicking four sections showed the highlight follows correctly).
